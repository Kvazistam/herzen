### 1. АКТУАЛЬНОСТЬ И ПРОБЛЕМА
*   **Проблема:** Большие языковые модели (LLM) дороги в инференсе и часто теряют структурную логику при генерации длинных нарративов («галлюцинации», нарушение сюжета).
*   **Решение:** Использование малых языковых моделей (SLM, ~124 млн параметров) с явным внедрением нарративных ограничений.
*   **Теоретическая база:** Теория «мономифа» (Пути героя) Дж. Кэмпбелла, адаптированная под жанр сказки (17 этапов).

### 2. ЦЕЛЬ И ЗАДАЧИ
**Цель:** Разработать SLM, способную генерировать связные сказки, строго соблюдающие этапы пути героя.

**Ключевые задачи:**
1.  Адаптировать 17 этапов мономифа к сказочному жанру и разработать систему теговой разметки.
2.  Реализовать архитектуру GPT-2 Small «с нуля» на PyTorch.
3.  Подготовить корпус данных (~2900 сказок) и реализовать двухэтапный пайплайн обучения (Base PT + LoRA FT).
4.  Провести сравнительный анализ качества генерации и структурного соответствия.

### 3. АРХИТЕКТУРА МОДЕЛИ (SLM)
Модель реализована на базе архитектуры Transformer (Decoder-only).

| Параметр | Значение | Обоснование |
| :--- | :--- | :--- |
| **Параметры** | ~124 млн | Баланс качества и возможности локального запуска |
| **Слои (Layers)** | 12 | Достаточная глубина для выявления синтаксических связей |
| **Hidden Size** | 768 | Стандарт для GPT-2 Small |
| **Головы внимания** | 12 | Параллельный учет разных типов зависимостей |
| **Контекст** | 512 токенов | Оптимально для короткой сказки, снижает $O(L^2)$ сложность |
| **Vocab Size** | 50,257 | BPE-токенизатор GPT-2 |

**Особенности реализации:**
*   Weight Tying (разделение весов эмбеддинга и выхода).
*   Gradient Clipping (порог 1.0) для стабильности.
*   Mixed Precision (AMP float16) для ускорения на GPU T4.

### 4. МЕТОДОЛОГИЯ ОБУЧЕНИЯ

**Этап 1: Continual Pre-training (Base Model)**
*   **Данные:** Конкатенация ~2900 сказок с токеном `<|endoftext|>`.
*   **Задача:** Next-token prediction.
*   **Гиперпараметры:** LR $6 \cdot 10^{-4}$ (Cosine Decay), Batch Size 524k (gradient accumulation), 5000 шагов.
*   **Результат:** Усвоение лексики и стиля фольклора. Loss снизился с 1.04 до ~0.28.

**Этап 2: Instruction Fine-Tuning с LoRA**
*   **Метод:** Low-Rank Adaptation (Rank=16, Alpha=32). Заморожены веса базы, обучаются только адаптеры в слоях Attention и MLP.
*   **Данные:** Пары «Промпт – Ответ». Промпты включают теги структуры (например, `<stage_call_to_adventure>`).
*   **Маскировка:** Токены промпта исключены из функции потерь (`ignore_index=-100`).
*   **Гиперпараметры:** LR $3 \cdot 10^{-4}$, 200 шагов.

### 5. АДАПТАЦИЯ СХЕМЫ КЭМПБЕЛЛА
Для управления генерацией использованы 17 структурных тегов. Примеры:

| Тег | Нарративная функция в сказке |
| :--- | :--- |
| `<stage_call_to_adventure>` | Появление проблемы/запрета |
| `<stage_supernatural_aid>` | Встреча с дарителем/получение артефакта |
| `<stage_crossing_threshold>` | Переход в иной мир (лес, царство) |
| `<stage_road_of_trials>` | Серия испытаний/загадок |
| `<stage_ultimate_boon>` | Получение цели (награды) |
| `<stage_freedom_to_live>` | Финал, восстановление порядка |

### 6. РЕЗУЛЬТАТЫ ЭКСПЕРИМЕНТОВ

**Динамика обучения (Base Stage):**
*(Здесь можно вставить маленький график Loss Curve из Главы 2)*
*   Стабильная сходимость без взрыва градиентов.
*   Норма градиента удерживается в диапазоне 0.5–1.0.

**Качество генерации (Qualitative Analysis):**
*   **Без тегов:** Модель генерирует связный текст, но сюжет хаотичен.
*   **С тегами Кэмпбелла:** Модель корректно отрабатывает запросы вида `Write a tale with stages: <call> -> <aid> -> <return>`.
*   **Пример вывода:**
    > *«<stage_call_to_adventure> Жила девочка Лира... услышала голос: "Ты нужна нам"... <stage_supernatural_aid> Явился старец... вручил кристалл...»*

**Сравнение подходов:**
| Метрика | SLM (Fine-tuned) | LLM (Zero-shot Prompting) |
| :--- | :--- | :--- |
| **Структурное соответствие** | Высокое (при наличии тегов) | Среднее/Низкое (требует сложных промптов) |
| **Стоимость инференса** | Низкая (локальный GPU/CPU) | Высокая (API/Cloud) |
| **Управляемость** | Высокая (через веса) | Средняя (через промпты) |
